## 四、关键设计决策

1. **不开自动交付，走 paid → 后台开通 → fulfilled**
   开通报价要下单、付款、等结果（可能数分钟），付款那一刻还没开通完。
   所以订单付款后停在 `paid`，后台线程开通成功再转 `fulfilled` 并触发交付邮件。

2. **下单前就校验用户名**（不等到付款后）
   买家填错的后果是「钱花了、Premium 开给了陌生人」。
   校验分三种结果：`invalid`（格式错）/ `not_found`（账号不存在）/ `not_eligible`（账号存在但收不了赠礼）。

3. **退款一律转人工**
   Premium 是直接开在买家账号上的，**开了撤不回来**。
   已开通（`succeeded`）或开通中（`processing`/`review`）的订单，退款接口直接拒绝并说明原因。

4. **幂等靠商城订单号**
   以 `order_id` 作为幂等锚点，重复提交不会重复赠送。
   商城侧另有 `_INFLIGHT` 集合防止同订单并发起两个线程。

5. **结果未明不重试**
   开通返回 `review`（结果待核实）时，只发告警，**绝不自动重试**，避免重复赠送。
